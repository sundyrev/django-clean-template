# Django Clean Template

A clean and production-ready Django project template that supports both local deployment (via Systemd, Nginx, and Gunicorn with Unix sockets) and containerized deployment (via Docker with TCP ports). It includes modern tools like `uv` for dependency management and is designed to help you start development quickly.

## Features

- Django 5.0 (latest stable version at the time of writing)
- Python 3.11
- Dependency management with `uv` (a fast alternative to `pip`)
- Gunicorn with Unix sockets for local deployment and TCP ports for Docker
- Nginx as a reverse proxy for serving static and media files
- PostgreSQL 13+ support
- Docker and Docker Compose for containerized deployment
- Split settings for `local` and `production` environments with `.env` files
- Jinja2 templating support alongside Django templates
- Pre-configured logging with separate log files for Django, Gunicorn, and Nginx
- Basic security settings for production

## Limitations

- Requires PostgreSQL (13 or higher); no MySQL support
- Configuration via environment variables; no Apache/mod_wsgi support
- Docker deployment uses TCP ports for simplicity; Unix sockets require additional setup

## Prerequisites

- **Python 3.11+:** Required for the project (managed via `pyenv`).
- **pyenv:** Must be installed to manage Python versions.
- **sudo privileges:** Required to install system packages and configure services.
- **Docker and Docker Compose:** Needed for containerized deployment (optional).

## Quick Start

1. Clone the repository:

   ```zsh
   git clone https://github.com/sundyrev/django-clean-template.git
   cd django-clean-template
   ```

2. Run the installation script:

   ```zsh
   sudo ./install.sh
   ```

   Follow the prompts to enter the domain name, project name, and environment (development or production).

3. Configure environment variables in `conf/env_vars/local.env` or `conf/env_vars/production.env`, especially `DATABASE_URL` and `SECRET_KEY` (auto-generated).

4. For local deployment, check Gunicorn status:

   ```zsh
   sudo systemctl status project_name.gunicorn.service
   ```

   Access the app: Open `http://<project_domain>` or `http://127.0.0.1` (for local dev).

5. For Docker deployment, build and run:
   ```zsh
   docker-compose up --build -d
   ```
   Access the app: Open `http://localhost`.

## Detailed Installation

1. **Clone the repository:**

   ```zsh
   git clone https://github.com/sundyrev/django-clean-template.git
   cd django-clean-template
   ```

2. **Run the installation script:**

   ```zsh
   sudo ./install.sh
   ```

   - You will be prompted to enter:
     - **Domain name:** e.g., `example.com` (without protocol).
     - **Project name:** e.g., `myproject`.
     - **Environment:** Choose `1` for Development (local) or `2` for Production.
   - The script will:
     - Install system dependencies (Python, PostgreSQL, Nginx, etc.).
     - Create the project structure.
     - Set up a Python virtual environment with `uv`.
     - Configure PostgreSQL, Gunicorn, and Nginx.
     - Generate a secure `SECRET_KEY` and update `.env` files.

3. **Configure environment variables:**
   - Edit `conf/env_vars/local.env` or `conf/env_vars/production.env` as needed:
     - Update `SECRET_KEY` (auto-generated by the script).
     - Adjust `DATABASE_URL` if using a custom database.
     - Set `EMAIL_*` settings for production email (e.g., SMTP credentials).

## Dependency Management

The project uses `uv` for fast and reliable dependency management. Dependencies are defined in `.in` files and compiled to `.txt` files.

To add a new dependency:

```zsh
echo "new-package>=1.0.0" >> project_name/requirements/local.in
uv pip compile project_name/requirements/local.in --no-emit-options --output-file project_name/requirements/local.txt
uv pip sync project_name/requirements/local.txt
```

## Local Deployment

- **Check Gunicorn status:**
  ```zsh
  sudo systemctl status project_name.gunicorn.service
  ```
- **Reload Systemd after changes:**
  ```zsh
  sudo systemctl daemon-reload
  sudo systemctl restart project_name.gunicorn.service
  ```
- **Access the app:** Open `http://<project_domain>` or `http://127.0.0.1` (for local dev).

**Note:** Local deployment uses a Unix socket (`/run/project_name.gunicorn.sock`) for communication between Nginx and Gunicorn, optimized for performance.

### Helper Scripts for Local Deployment

  - Usage:
    ```zsh
    ./gunicorn.sh
    ```

- **`runserver.sh`:**
  - Starts the Django development server for quick testing.
  - Usage:
    ```zsh

    ```

## Docker Deployment

1. **Build and run containers:**

   ```zsh
   docker-compose up --build -d
   ```

   - This starts Django, Nginx, PostgreSQL, and Redis containers.
   - Django listens on `0.0.0.0:8000` (TCP port) inside the container.

2. **View logs:**

   ```zsh
   docker-compose logs nginx
   # Real-time logs
   docker-compose logs -f django
   ```

3. **Access the app:** Open `http://localhost` or your domain (if configured).

### Deployment Script

- **`deploy.sh`:**
  - Automates building and deploying the Docker setup.
  - Usage:
    ```zsh
    ./deploy.sh
    ```

**Note:** Docker uses TCP ports (`8000` for Django, `80`/`443` for Nginx) instead of Unix sockets for simplicity and container compatibility.

## Why Sockets Locally and TCP in Docker?

- **Local (Unix Sockets):** Optimized for performance on a single machine, avoiding network overhead.
- **Docker (TCP Ports):** Standard for containerized environments, as Unix sockets require shared volumes and are less common in Docker setups.
- This intentional split allows flexibility: local development can skip Docker builds, while Docker provides a portable production-like environment. For consistency across all environments, consider using TCP ports everywhere (see "Best Practices" below).

## Best Practices

- **Consistency:** For larger projects or team collaboration, use TCP ports (`127.0.0.1:8000` locally, `0.0.0.0:8000` in Docker) everywhere to avoid configuration differences.
- **Security:** Update `production.env` with a strong `SECRET_KEY` and enable HTTPS in production (uncomment HSTS headers in `docker.conf`).
- **Monitoring:** Integrate Sentry (included in `production.in`) by setting `SENTRY_DSN` in `production.env`.

## Cleanup

To stop and remove the project, use the provided `delete.sh` script or manual commands:

- **`delete.sh`:**

  - Stops and removes all project-related services, files, and Docker containers.
  - Usage:
    ```zsh
    sudo ./delete.sh
    ```

- **Manual Cleanup (Alternative):**
  - **Local:**
    ```zsh
    sudo systemctl stop project_name.gunicorn.service
    sudo systemctl disable project_name.gunicorn.service
    sudo rm /etc/systemd/system/project_name.gunicorn.*
    sudo systemctl daemon-reload
    sudo systemctl restart nginx
    rm -rf <project_directory>
    ```
  - **Docker:**
    ```zsh
    docker-compose down -v
    ```

## Troubleshooting

- **Gunicorn fails to start:** Check logs in `log/gunicorn.log` or `systemctl status`.
- **Nginx errors:** Review `log/nginx/error.log` or `docker-compose logs nginx`.
- **Database issues:** Verify `DATABASE_URL` in `.env` files and ensure PostgreSQL is running.
